# Operational gotchas (read before touching anything)

- **`uvicorn --reload` watches only `.py` files — after editing `.env` the backend MUST be restarted manually.** "Gemini is not configured" with a key in `.env` = stale process. Also the project lives in OneDrive, where WatchFiles reloads are unreliable — restart after code changes too (the last server runs WITHOUT `--reload` for this reason).
- Run the backend from `backend/` (`Settings` reads `.env` relative to CWD): `cd backend && .\venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000`.
- `backend/.env` is gitignored; `backend/tests/conftest.py` pins `OPENAI_MODEL`/`LLM_PROVIDER`/`MOCK_LLM` so tests never inherit the developer's `.env` — keep it that way.
- Story creation writes to the real `story.db` — smoke-test with `DATABASE_URL=sqlite:///./smoke.db` and delete it after.
- **A wedged backend: kill the process that holds port 8000, not the one you started.** Symptom: the page shows "No stories yet" and "Loading story…" forever, while `http://127.0.0.1:8000/api/health` *times out* (a refused connection means the server is down; a timeout means something accepted the socket and never answers). Check `netstat -ano | findstr :8000` and `Stop-Process -Id <pid> -Force` — with `--reload` an OLD instance can keep the listening socket while a freshly started one sits in front of it doing nothing, and on Windows two sockets can bind the same port, so the newer process silently never receives a request. Two usual triggers: the `--reload` watcher wedging (OneDrive + WatchFiles is flaky — restart without `--reload` after code changes) and many files being written under `backend/data/`, which is inside the watched tree; add `--reload-dir app` if you keep `--reload`.
- **`--reload` also leaves orphaned children that serve the OLD code.** Killing the `uvicorn` parent is not enough: the worker child survives, keeps the port, and answers requests from the module it imported at start. This looks exactly like "my change did nothing" — the API returns the previous shape and a restart seems to fix nothing. `Get-NetTCPConnection -LocalPort <port> -State Listen` returns a PID that `Get-Process` may already report as gone (a stale socket entry), so list every `python`/`uvicorn` process and read its command line, or `taskkill /PID <pid> /T /F` on the owning PID until it is really gone. Clear `backend/app/**/__pycache__` too whenever the served behaviour is wrong after a restart. Verify the fix against the API, not the log file: an old process keeps writing to the same `server_err.log`.

- **`IMAGE_DIR` is relative to the server's working directory, so run the backend from `backend/`** — the pictures then live in `backend/data/images/`, while a server started from the repo root silently uses a *different*, empty `data/images/` (the portraits break as "alt text only" while the database still lists them). ComfyUI keeps its own copy of every picture it drew under `ComfyUI/output/roleplaygen/story_<id>/` (`scene_<turn>_*.png`, `portrait_<char>_*.png`); that folder is the recovery source when `IMAGE_DIR` loses its files.
- Full checks: `cd backend && pytest` and `cd frontend && npx vitest run && npx tsc --noEmit`. Run both before declaring a task done; do not paste hardcoded test counts into docs — they go stale.

## Backend (Python)

- **A module-level alias must come AFTER the function it names.** `init_portrait_history = _init_history` placed next to `_history_entry` (which is *above* `_init_history`) is a `NameError` at import time, and it surfaces as a bare `ImportError while loading conftest` from pytest — a long way from the line that caused it. Assign the aliases below both definitions.
- **`conftest.py` pins `IMAGE_GENERATION_ENABLED=false`**, so an endpoint that queues a picture job stores the new data but leaves the status alone. Assert on what was STORED (the look, the history length), not on `status == "queued"`, or the test fails for a reason that has nothing to do with the code under test.
- **Adding a required field to a Pydantic response model breaks every TypeScript fixture.** Declare the matching TS field optional (`field?: string | null`) when the backend value is a defaulted optional — the fixtures build whole objects, not partials.

## Frontend (React)

- **A `catch` that sets an error banner and then resolves is a silent SUCCESS to every caller.** `StoryPage.submitChoice` did exactly that, so `ChoicePanel` believed the turn had landed and cleared the player's typed action and note after a failed request — the data was destroyed by the code that reported the failure. Rethrow after showing the banner whenever a child component owns input the user would hate to lose.
- **Never use a prop OBJECT as a `useEffect` dependency to mean "this turn changed".** The parent recreates it on every render, so the effect re-ran each time and undid the component's own state (the draft was read back from storage right after a successful submit cleared it). Use the turn's stable identity — its id, or its content such as prompt + option ids.
- **`sessionStorage` writes must be debounced and wrapped in try/catch.** Private mode and storage-disabled browsers throw; a draft that cannot be persisted must degrade to "works until reload", never to a broken panel.
- **Async `setState` after an `await` does not settle inside a plain `fireEvent`.** A test that clicks and then asserts sees the pre-update DOM; wrap the click in `await act(async () => …)`. Symptom: a passing component whose test fails for no visible reason.

## Pictures (ComfyUI)

- **A fixed sentence in the scene prompt is worse than no sentence.** `assemble_scene_caption` once appended "She stands upright and still, both feet planted on the ground, weight even, spine straight…" to every scene mentioning standing, to fight a leaning character. Qwen-Image reads repetition as emphasis, so those constant words became the loudest instruction in the prompt and pinned her standing in one spot, in one stance, for a whole story. The backend contributes the medium, the identity anchors and the world — **never a pose, a framing or a camera side**; those belong to the narrator's sentence, which is the only part that varies per turn. `test_a_scene_prompt_never_appends_a_fixed_pose` guards it.
- **A stored look is a tag pile until it is trimmed.** A 63-tag danbooru look becomes ~60 words of caption, four fifths of the prompt, half of it about the chest — it decides the crop and the pose of every picture. `look_anchor` reduces it to identity anchors; a look of ≤12 items is an ordinary English phrase and passes through untouched.
- **The edit encoder's picture inputs are NAMED, not a list.** The current `TextEncodeQwenImage21` takes `images.image_1`, `images.image_2`, … A list written to `inputs["images"]` is accepted and **silently ignored**, so every scene renders with no reference at all and no error. `build_edit_workflow` writes one named socket per slot and deletes the template's own `images.image_*` keys first.
- **The canvas comes from `ResolutionSelector`, not from `EmptyLatentImage`.** The img2img chain must scale a reference to the exact size the sampler uses, so `workflow_resolution` resolves the selector's `aspect_ratio` + `megapixels`; a workflow whose selector cannot be read falls back to the old hardcoded sizes instead of failing the job. Real canvases are 1632x920 and 1000x1504.
- **Repainting overwrites the same file, so the URL must change.** Pictures are named after the row (`<story>/<turn>.png`), so without the `?v=<version>` counter the browser revalidates, `StaticFiles` answers "304 Not Modified", and the new picture is drawn but never displayed. The counter is bumped where the bytes are written — in every path, including the restart-adoption ones.
- **A repaint must clear `image_build_log`.** A re-queued job reuses the seed its log records (so an interrupted picture comes back as itself); a repaint has to NOT reuse it, or "repaint" redraws the identical picture.
- **Check the seed is actually varying before blaming it for a repeated composition.** `image_build_log` records the seed of every picture; compare a few turns before looking anywhere else. Turns drawn before `IMAGE_SEED_MODE` existed all carry the base seed, so an old story looks broken until it is repainted.
